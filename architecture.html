SYSTEM DESIGN

Proposed Architecture

An evidence-grounded pipeline connecting heterogeneous data, knowledge graphs, query interpretation, graph ranking, retrieval, and human investigation.

High-Level Architecture

Data Sources Case data · Documents · Public data · Authorized sources
↓
LLM / NLP Extraction Entities · Relationships · Events · Semantic information
↓
Entity Resolution Resolve references to real-world entities
↓
Investigative Knowledge Graph Entities · Relationships · Evidence · Time · Provenance
↓
Investigator Query Natural-language investigative question
↓
Query Interpretation Relevant entities · relationships · time · context
↓
Query-Dependent Markov Ranking Graph · relevance · evidence · time · trust · anomaly
↓
RAG + Evidence Retrieval Retrieve supporting records and source material
↓
LLM Explanation Explain ranking factors and supporting evidence
↓
Human Investigator Review · verify · challenge · decide

1. Investigative Knowledge Graph

The graph represents a heterogeneous collection of entities and relationships rather than simply a social network.

Possible entities

  • People
  • Organizations
  • Locations
  • Vehicles
  • Devices
  • Telephone numbers
  • Bank accounts
  • Transactions
  • Events
  • Documents
  • Online identities
  • Addresses

Possible relationships

  • Called
  • Messaged
  • Emailed
  • Met
  • Visited
  • Paid
  • Transferred money
  • Owned
  • Worked for
  • Traveled to
  • Used
  • Mentioned in

2. Evidence as a First-Class Graph Component

A relationship should not exist in isolation from the evidence supporting it.

Alice
→
called
→
Victim
Supporting evidence
  • Timestamp: 21:32
  • Duration: 8 minutes
  • Source: Telephone record
  • Evidence type: Structured record
  • Reliability: High
  • Supporting document: Record #182

This allows the graph to function as an index over evidence rather than a replacement for the evidence itself.

3. Query Interpretation

The investigator's natural-language question becomes a first-class input to the ranking system.

"Who communicated with the victim during the six hours preceding the event?"

An LLM or other query-understanding component could extract:

  • Target entity: Victim
  • Time window: Six hours preceding event
  • Relationship type: Communication
  • Preferred evidence: Direct and reliable records

These parameters then influence the ranking process.

4. Ranking Features

Graph Structure

Connectivity, path length, centrality, and structural relationships.

Semantic Relevance

How closely the relationship matches the investigator's question.

Evidence Strength

Reliability, corroboration, specificity, and evidentiary quality.

Temporal Relevance

Distance between an observed event and the relevant investigative time.

Source Trust

Reliability and authority associated with the information source.

Anomaly

Unexpected or missing relationships relative to an established baseline.

5. False-Flag Analysis

High relevance does not necessarily mean wrongdoing. A relationship can be highly visible for completely innocent reasons.

  • Shared workplace
  • Shared residence
  • Family relationship
  • Common service provider
  • Geographic coincidence
  • Routine commercial activity
  • Entity-resolution error
  • Incomplete data

The system should therefore expose alternative explanations rather than produce an opaque "suspicion score."

Important distinction: Investigative relevance is not a probability of guilt.

6. Human-in-the-Loop Design

The system is intended to prioritize information, not replace investigative judgment.

System

Ranks and explains

↔
Investigator

Reviews and challenges

↔
Evidence

Supports or contradicts

Every significant ranking contribution should ideally be traceable to an underlying record.
